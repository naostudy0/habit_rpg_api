# AI運用方針

## 目的
本ドキュメントは、Habit RPG API における AI 活用時の共通ルールと、人間と AI の責任分界を明文化することを目的とする。

## 適用範囲
- コード生成
- テスト生成
- ドキュメント作成
- 調査、要約、レビュー補助
- Issue / PR 作成補助

## 基本原則
1. AI は支援者であり、最終判断者ではない。
2. 人間が要件判断、レビュー、承認、マージ、公開可否の最終責任を負う。
3. AI による出力は常に誤りを含み得る前提で扱い、根拠確認を行う。
4. 変更は小さく、追跡可能で、レビューしやすい単位に保つ。

## 責任分界

| 項目 | AI が担うこと | 人間が担うこと |
| --- | --- | --- |
| 要件整理 | 既存情報の整理、論点抽出、叩き台作成 | 要件決定、優先順位判断 |
| 実装 | コード、テスト、ドキュメントの草案作成 | 妥当性確認、採否判断 |
| 品質確認 | 差分確認、テスト実行補助、レビュー補助 | 最終レビュー、マージ判断 |
| セキュリティ | 既知パターンの注意喚起 | 秘密情報管理、権限判断、公開判断 |
| 運用 | 手順書、コマンド、設定案の提示 | 本番操作、権限付与、障害判断 |

## 共通ルール
1. 秘密情報、個人情報、トークン、秘密鍵を AI 入出力に含めない。
2. AI が生成したコード、SQL、設定値、ドキュメントは人間が確認してから採用する。
3. 要件が曖昧な場合、AI は推測で確定せず、前提や不明点を明示する。
4. 破壊的な操作、権限変更、データ削除、本番影響のある変更は人間の明示承認を前提とする。
5. 仕様変更や運用変更を伴う場合、必要な関連ドキュメントも同時に更新する。
6. 変更時は、可能な範囲でテストや静的チェックを行い、未検証部分があれば残課題として共有する。
7. Issue、PR、コミット、ドキュメントのいずれかで、変更の背景と意図を追跡できる状態を保つ。

## AI に任せてよい主な作業
- 既存コードの読解と要約
- 実装案、リファクタ案、テスト観点の提案
- 小規模から中規模のコード変更
- ドキュメント、README、運用手順の草案作成
- レビューコメントの整理と差分の観点出し

## 人間の確認が必須な作業
- 本番環境への反映
- 秘密情報や認証情報の取り扱い
- セキュリティ、法務、ライセンス上の判断
- DB データ修正や削除を伴う運用判断
- 要件変更、仕様凍結、マージ可否の判断

## レビュー時の確認項目
1. 要件に対して過不足のない変更か。
2. セキュリティ、個人情報、認可まわりに問題がないか。
3. テストや確認手順は十分か。
4. ドキュメント更新が必要な変更を漏らしていないか。
5. 不明点、制約、未対応事項が明示されているか。
